为什么同样是让 AI 干活，Prompt 聊着聊着容易失焦，但 Skill 可以让 Agent 稳定完成一个复杂任务？

这两天我们门店要开一个新的短视频栏目，需要做配音。我想起去年做过一个 CosyVoice 声音克隆的 App：一个网页界面，输入文字，就能快速生成我克隆过的语音。

这个 App 当时也是 ChatGPT 帮我做出来的，但今年再遇到同样需求时，我发现工具又往前走了一步。

我没有再重新做一个网页 App，而是把这套能力封装成了一个 Skill。

也就是说，它甚至不需要网页界面了。

我把相关脚本、资源、操作流程、样板和范例都打包进 Skill 里，以后只要把这个 Skill 安装到常用的 Agent 里，不管是 Claude Code、Workbuddy，还是 Hermes Agent，都可以直接通过交互完成音频生成任务。

这其实正好说明了 Skill 和 Prompt 的区别。

Prompt 更像是一次性的文本指令：

你告诉 AI，这次要怎么做。

而 Skill 更像是一个可复用的、结构化的专业能力包，里面不只有提示词，还有指引文档、操作流程、脚本、模板、范例，以及理想输出格式。

也正因为有了 Skill，Agent 才更适合执行长流程、复杂、重复的任务，而不是每次都靠一段临时提示词，在多轮对话里慢慢跑偏。

从现在开始，我们可以把真实工作现场里那些重复、繁重、复杂的流程，逐渐封装成可以复用、可以迁移、可以交给 Agent 执行的 skill。

Prompt 让 agent 听懂你这一次，而 skill 可以让它代替你完成这一类事情。
