Claude Code 创始人 Boris Tane分享过他使用Claude心得 -

绝不会直接让 Claude 写代码，除非他们已经一起讨论出一份书面计划，并且这份计划经过他的审批和批准。

这其实就是很严格地把「计划」和「执行」分开。

为什么这件事重要？

因为 LLM 的底层工作方式，本质上是从左到右、逐个 token 做预测。

训练时，其实是海量的数据输入，建立与输出的对应关系和映射，封装内化成模型的参数和权重，在我们日常使用时依此进行预测。

所以它会顺着当前上下文的统计概率往下接话，但它天然不是一上来就做全盘统筹。

这也是为什么Andrej Karparthy把它比喻成一个极其昂贵、极其华丽的自动补全工具。

所以如果我们不给它特殊引导，直接让 Agent 开始生成内容，就像要求一个人从第一个字一口气写到最后一个字，中途还不能用退格键修改。

它当然容易缺乏全局观，前面写错了，后面就要不断补救。

而Boris 给出来的解法是三步走：

1/先充分调研，要求Agent就工作区里面的相关资料进行深入阅读和探索，注意带上深入；

2/再基于调研做规划，规划阶段人类加入进来，讨论、修改、注释，让 Agent 反复调整；

3/等大方向和架构决策都确认之后，才进入实施。

我自己现在把这套方法做成 skill，让 Agent 按这个步骤执行任务，效果确实会好很多。

不是因为 Agent 突然变聪明了，而是因为在它执行之前，已经先被迫建立了一次全局观。

Agent 使用中，预则立，不预则废，也同样适用。
